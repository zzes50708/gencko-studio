# 競標登入與官方驗證第二輪複驗

本輪延續 LINE 登入及官方驗證的操作排查，未提交或部署。首頁前一輪的修改仍保留。

## 已重現並修正的問題

1. **跨帳號殘留輸入**：尚未出價時，切換會員仍會保留前一位的公開暱稱與金額。現在依會員 ID 切換清空；同會員的 session 更新不清空輸入。原帳號已送出而結果待確認的請求仍保留在該帳號的 sessionStorage，切回時可以恢復。
2. **離線輪詢**：建立官方驗證碼後，離線仍每五秒嘗試查詢。現在離線不發出輪詢，恢復連線再查核；到期仍會清除舊碼。
3. **驗證重複請求**：連按重新確認並同時回前景，重現四筆並行查詢。現在同一會員／場次最多共用一筆進行中查詢。卡住最多等待十秒，提示重試；舊請求不再覆蓋新的結果。
4. **複製完成時已過期**：剪貼簿權限延遲完成，會替已過期的驗證碼顯示成功。現在成功及失敗分支均再次檢查期限；過期立即隱藏舊碼。
5. **狀態查詢無截止時間**：慢速／中斷網路會長時間卡住查詢。現在十秒取消並提供重新確認，未確認時不開放新的出價。
6. **建立驗證碼無截止時間**：會持續顯示建立中。現在十秒結束等待，能重新建立。
7. **SDK 尚在取得憑證時無法結束**：單靠 fetch AbortSignal，SDK 在送出請求前等待 getSession 時仍可能卡住。已以 Promise.race 將逾時涵蓋整段 SDK 操作；憑證稍後恢復時，已取消的舊查詢不會補送。

另外補上生命週期保護：離頁／切換會員取消在途請求，清除計時器；若建碼尚未返回、其他查詢已確認通過或限制出價，不採用較晚的建碼結果重新輪詢。

## 測試調整的原因

- 原出價故障測試早於官方 LINE 強制驗證，未提供驗證 RPC 的隔離回應，導致正式頁面正確停用出價。測試補上已驗證回應與固定 session，沒有更改正式資格檢查，也沒有直接操作元件將驗證設為通過。
- 舊延遲回應案例刻意同時持有兩筆查詢；查詢改為合併後，改驗證「十秒取消舊請求、未確認期間禁止出價、重試取得最新狀態、舊結果不能推翻新結果」。裝置日期正常、快兩天及慢兩天都須通過。

## 驗證範圍

- 新增跨帳號清除、同帳號保留、建碼與已驗證競態、離線恢復、查詢合併、延遲剪貼簿、兩種網路逾時與 SDK 憑證等待案例。
- 出價故障回歸涵蓋舊價格／結標時間、輸入保留、回應遺失重試、空回執、401、結標、連點、暱稱、取消、重載、帳號切換、原請求恢復、舊帳號回執及手機表單。
- Supabase 唯讀權限檢查：永久 LINE 出價驗證表啟用 RLS、匿名不可讀、會員不可直接插入。未更改正式資料、驗證紀錄、出價或付款。

最終整批 48 項瀏覽器案例通過（含一組內部 19 種出價故障情境），40 項登入／會員／出價契約／詳情單元測試通過。程式碼格式及差異檢查通過。

隔離正式建置成功（程序結束碼 0）；最新產物的六項競標 SSR 回歸通過：最高價、無出價、資料故障不捏造價格、結標禁止索引、詳情與列表資料不可注入腳本。

## 實機界線

本輪使用本機頁面、實際 Supabase SDK 與隔離的授權／資料回應。未在使用者實體 Android 手機執行原生 LINE 跳回 App，未發送官方 LINE 訊息，也未宣稱已完成實機驗收。
