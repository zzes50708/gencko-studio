# 一次性官方 LINE 出價驗證（2026-10-21）

本紀錄取代先前「manual_claim 模式不需出價前驗證」的規則。最新需求：每個 LINE 帳號首次出價前，必須從同一 LINE 向官方帳號傳送驗證碼；通過後永久保留資格，棄標等限制另外處理。

## 儲存與授權

- 永久資格保存在 Supabase private.auction_line_bid_verifications，以 LINE 供應商識別為主鍵，保存 verified_at，沒有六個月到期或聊天紀錄依賴。
- authenticated／anon 無法自行寫入；只在通過 LINE Webhook 簽章、有效驗證碼與登入 LINE 身分比對後記錄。
- 純登入、普通訊息、加好友不授予資格；歷史資料只承認同 LINE 且有 line_contact_verified 事件的紀錄。
- 所有場次（含 workflow_enabled=false 的非販售測試）在資料庫出價函式強制檢查；通知與領標模式不再略過驗證。
- 棄標限制依真實 LINE 身分與會員識別檢查，獨立於永久驗證表；聯絡列缺漏也不能繞過。
- LINE 對話紀錄清除、換裝置、重新登入不影響資格；不承諾資料庫刪除、服務停用或 LINE 換帳號後仍沿用。

## 畫面與恢復

- 所有出價頁掛載驗證區塊，不以付款流程開關決定是否顯示。
- 首次說明只需傳送一次；已驗證後顯示已驗證，不再要求重新建立。
- 返回網站、恢復連線、回前景補查；同一批恢復事件合併，離頁移除監聽。
- FAQ 同步改為首次驗證後出價，得標後仍需逐場領標。

## 實際驗證

- 正式 Supabase 已套用 auction_once_line_verification 與 auction_line_restriction_identity 兩個遷移。
- 唯讀確認正式出價函式包含資格檢查、永久表存在且 authenticated 無 INSERT 權限。
- 外層 BEGIN／ROLLBACK 交易驗證通過：未驗證拒絕、錯 LINE 拒絕、正確驗證碼授權、驗證後可出價、取消追蹤仍保留資格、限制獨立且聯絡列缺漏仍拒絕。
- 測試出價與資料異動全部回滾，未發送 LINE 訊息、未保留測試出價或限制。
- 37 項單元／API 測試通過；19 個瀏覽器案例均已通過（整合先通過 18 個，修正舊測試自動恢復競態後，剩餘 1 個重跑通過）；SSR 六項驗證通過。
- 正式前端建置通過；最新前端尚未部署。正式資料庫已開始強制驗證；舊前端的非付款測試場次尚無入口，須搭配前端部署。
- 真正 Android 安裝版與 LINE App 回程仍需部署後真機驗收。

最初使用內部子交易的資料庫測試被自動審核拒絕；後改為明確外層 BEGIN、5 秒 statement_timeout、ROLLBACK，測試獲准並通過。
