# 節點 56：爬櫃模型更新與旋轉流暢度

## 根因與修改

原本改變層數會同時改變面光源數量、LED 邊界陣列長度及材質程式快取鍵。4 層切成 8 層時新增 56 個著色器編譯，造成第一次更新長時間等待。

- 面光源保留 8 個槽位；實際層數改用 uniform，跨層數共用 GPU 程式。
- 面光源改用動態迴圈，不逐層展開完整 LTC 計算；關閉及不在該層範圍內的光源略過運算，維持原本遮光邊界。
- 共用幾何、材質與繪製種類的物件只預編譯一次，避免每個抽屜重複提交。預編譯去重保留幾何、材質、實例顏色與接收陰影的區別。
- 沒有調低貼圖、陰影、透明盒體材質或厚度。更新中操作與最後配置生效保留。

## 量測

硬體：NVIDIA GeForce GT 1030、ANGLE D3D11；390px 觸控視窗。每個版本使用一個瀏覽器、三個新 context。第二、第三次會受到驅動程式快取影響，不能視為三個獨立冷啟動。

| 樣本 | 修正前初載 | 修正後初載 | 修正前 8 層更新 | 修正後 8 層更新 |
| ---- | ---------: | ---------: | --------------: | --------------: |
| 1    |     7730ms |     3484ms |         13483ms |           547ms |
| 2    |     2105ms |     1705ms |           708ms |          1027ms |
| 3    |     2026ms |     1704ms |           705ms |           506ms |

首次更新的顯著等待已縮短；熱快取下的更新仍有波動，不宣稱每次更新都有固定改善比例。修正後更新期間三次皆未記錄到超過 50ms 的 longtask，初載仍有約 489ms 的長任務。

正式版本三次初載為 2821／1037／1051ms，8 層更新為 1045／1029／1034ms。這是另一輪正式版本量測，不能直接與開發版當作相同條件比較。

8 層、40 抽、全層 LED 開啟的旋轉測試：390px 與 1440px 的 rAF 畫格間隔第 95 百分位均約 16.7ms，沒有頁面執行錯誤。此數值是主執行緒畫格間隔，並非實體手機或 GPU 呈現時間保證。
