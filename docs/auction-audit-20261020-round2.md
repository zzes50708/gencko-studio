# 競標完整複驗第二輪（2026-10-20）

## 三項修正

1. 管理頁沒有持續更新時間，預約／進行中篩選及場次標籤可能停在舊狀態。新增輕量時鐘，隱藏頁面暫停週期更新、返回前景立即更新、離頁清理；統一採用公開競標相同的狀態判定。瀏覽器測試先重現失敗再確認修正。
2. LINE 聯絡狀態允許重疊查詢，舊的未驗證結果可能覆蓋新的已驗證結果。加上查詢序號，錯誤與成功回應都只能由最新查詢寫回；保留會員／場次切換的隔離。瀏覽器測試先重現失敗再確認修正。
3. 網站 API 有檢查 Google／LINE 登入，但資料庫出價函式缺少相同限制。已加入依 `auth.identities` 的實際身分查核，不採用使用者可修改的個人資料；API 將該拒絕明確標為未成立，避免誤示為待確認出價。回滾測試重現舊行為後，套用 `20261020032204_auction_bid_provider_guard.sql`，再驗證不支援身分被拒絕、Google 與 LINE 均可正常出價。

## 實際資料庫同時提交驗證

使用本次新建的非販售場次 `TEST-CONCURRENCY-20261020-01`，不修改既有客戶場次：

- 已授權的 Google 與 LINE 測試身分同時送出 500 元，只有一筆成立；另一筆明確收到最低金額拒絕。
- 成立請求同時重送，兩個回應皆為同一筆原始出價；資料庫仍只有一筆出價與一筆請求。
- 子交易內測試壓線出價確實延長 3 分鐘；同一請求重送不再延長。
- 子交易內測試已到截止時間的新出價被拒絕，沒有留下被拒絕的出價。
- 此為雙身分競態與重送驗證，不是大量使用者負載壓力測試。

清理時 Supabase 連接器多次回傳 `Invalid or expired requestState`。先暫停本測試場次，避免意外結算，再透過既有授權的 CLI，以場次名稱、品系、狀態、註記及沒有結算紀錄為防護執行精確清理。最後查核場次、出價、請求、結算均為 0。沒有發送 LINE 或啟動客戶付款期限。

## 至少十項驗證涵蓋

1. 雙身分同額競爭。
2. 同一請求同時重送。
3. 壓線出價延長時間。
4. 重送不重複延長。
5. 截止後拒絕新出價。
6. 被拒絕出價不留錯誤價格。
7. 不支援的登入方式直接呼叫資料庫被拒絕。
8. 偽造個人資料不能冒充 Google 身分。
9. 合法 Google 會員仍可出價。
10. 合法 LINE 會員仍可出價。
11. 管理列表到開標時更新篩選。
12. 管理列表到截止時更新篩選。
13. LINE 舊狀態回應不覆蓋新驗證。
14. 上架重送、立即及預約開標回歸。
15. 核帳、限制範圍、登出清除資料回歸。
16. 超過一千筆出價分頁讀取的單元回歸。
17. 重新產生領標碼使舊碼失效。
18. 過期領標碼拒絕且不誤標已領標。
19. 新領標碼正常使用。
20. 已使用領標碼即使換新事件編號也不能重用，僅留下單一領標紀錄。
