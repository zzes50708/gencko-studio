# 節點 20：爬櫃原生手勢與更新

2026-10-06 完成補驗，沒有為未重現的問題修改產品行為。

## 驗證

- 使用 Chromium CDP 的原生 touchStart／touchMove／touchEnd，兩個觸點有獨立 id。沒有直接設定相機位置代替手勢。
- 單指拖曳確實改變相機觀察方向，旋轉前後相機距離一致。
- 雙指向外滑動縮短相機與模型中心距離，縮放成功；觀察到近距離限制約 5.5。
- 模型更新期間層數選項仍可開啟，更新提示不接收指標事件（pointer-events:none）。
- 8 層後接著選 3 層，完成後模型包含 6 個抽盒、摘要為每層 2 抽 × 3 層；aria-busy 回到 false。
- 調整配置前後觀察方向內積 > .98，沒有重設為正面。
- 關閉選單解除背景捲動鎖，離頁移除工作區。
- 2 項 Playwright 測試通過（27.4s），tests/e2e/cabinet-touch-ux.spec.ts。

## 限制

- 這是瀏覽器原生輸入模擬，不是實體手機、Safari 或 GPU 效能驗收。
- 初次審查腳本等待畫布只有 5 秒，冷載入未完成而失敗；改為等待實際畫布與 aria-busy 完成後進行測試，沒有以固定延遲判定手勢正常。
- 保留材質與建模邏輯，未修改產品檔案、未部署。
