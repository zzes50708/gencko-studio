# 客人得標、領標與付款復原複驗

延續競標全流程排查。修改留在本機，未提交或部署；正式 Supabase 只有唯讀檢查，未更改會員、出價、付款、場次或永久 LINE 驗證。

## 已重現及修正的十個情境

| 情境               | 修正後行為                                               |
| ------------------ | -------------------------------------------------------- |
| 個人競標歷史卡住   | 十秒後顯示讀取錯誤，可重新載入，不當作沒有出價           |
| 得標紀錄列表卡住   | 十秒後退出等待並提供重試                                 |
| 單場得標查詢卡住   | 十秒後顯示錯誤；不與「沒有可領標紀錄」同時呈現           |
| 領標訊息產生卡住   | 十五秒後可重試，沒有有效回應就不顯示訊息                 |
| 付款回報結果不明   | 十五秒後提示先重讀；未成功查核前停用交易操作，不自動重送 |
| 棄標結果不明       | 同樣先重讀，另用棄標專屬文案，避免誤提示付款             |
| 剪貼簿一直等待     | 十秒後提供手動複製，保留已取得且有效的原領標訊息         |
| 校時後領標碼已過期 | 複製成功及失敗返回時再次驗證期限，立即撤下過期訊息與入口 |
| 會員頁離線背景更新 | 離線停止競標歷史查詢，恢復連線補查                       |
| 離開會員頁         | 取消未完成的得標讀取，不讓舊結果回填                     |

得標、領標與交易請求使用共用等待上限，涵蓋 SDK 取得憑證及網路階段。切換帳號、更新初始得標資料、切換場次或離頁時取消舊等待，並保留原有的請求代次核對。

「停用交易操作」只維持到重新讀取成功。若重讀失敗，繼續顯示錯誤，不根據舊資料開放操作。現行由工作室核帳的手動領標場次仍不提供客人自行確認收款；付款回報的測試涵蓋既有通知流程。

剪貼簿 API 無法由網站強制撤銷系統權限視窗或已交給系統的複製動作，本輪取消的是前端等待與過時提示，不宣稱能控制手機作業系統。

## 驗證紀錄

- 十個新增的隔離瀏覽器情境全部通過，包含逾時後重試、領標碼保留、交易不自動重送及重新查核後切換狀態。
- 五十八項單元測試通過，包含得標資料檢查、會員歷史分頁、等待上限、管理請求、上架欄位、登入及出價契約。
- 正式資料庫唯讀核對：得標表開啟 RLS，匿名與會員不能直接讀表，會員不能直接修改表；客人端相關函式使用登入身分與得標者欄位進行核對。未用真實客戶帳號執行交易。

- 整批九十項瀏覽器回歸通過，涵蓋登入接續、官方 LINE 驗證、出價故障、會員歷史、領標、核帳與上架。
- 隔離正式建置成功（程序結束碼零）；最新產物的六項 SSR 驗證通過：最高價、無出價、故障不捏造價格、結標禁止索引、詳情與列表資料不能注入腳本。
- 程式碼格式與差異檢查通過。

## 驗證界線

瀏覽器測試使用本機實際頁面與 SDK，以及隔離的授權、得標和寫入回應；不代表已完成實體 Android 原生 LINE 跳轉驗收。未發送官方 LINE 訊息，沒有進行真實付款、付款核帳或棄標。
