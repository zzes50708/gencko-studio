# 授權失敗與驗證碼操作排查（2026-10-21）

## 問題與修正

- 取消 LINE／Google 授權後，回到網站沒有明確提示。新增失敗回程辨識，取消與其他錯誤顯示固定說明。
- 失敗回程的 error／error_description 殘留網址，重新整理可能持續錯誤。只在失敗回程清理，保留原篩選與一般錨點；不顯示供應商原始描述。
- Google 再次登入使用未清理的目前網址，可能帶舊 code／state／錯誤。兩種登入共用回程清理；成功回程的 code／憑證不被錯誤處理器提前移除。
- Google 登入無互斥保護，與 LINE 同時開始可能覆蓋 PKCE 流程。改共用登入請求鎖；失敗後恢復可重試。
- 驗證碼於輪詢間隙過期後仍能複製舊碼，已用重新校時重現。複製與前往 LINE 都在操作當下再檢查到期，過期即撤下並提供重建。
- 輪詢下一次檢查時間不再固定超過到期點；依剩餘時間縮短，清除過期碼時也撤下舊複製提示。

## 驗證範圍

- 40 項單元／API 測試通過。
- 新增取消授權 query／fragment、重整不重複提示、敏感描述不公開、兩種先後順序登入互斥、失敗重試及 Google 乾淨回程驗證。
- 新增輪詢間隔過期後複製與開啟 LINE 均被阻止、未寫入剪貼簿且沒有打開新分頁的案例。
- 最終 26 個瀏覽器整合案例全部通過（52.9 秒）；正式建置及 SSR 六項隔離驗證通過。
- 正式 Supabase 唯讀核對：競標管理員共 1 個，且只有指定管理員帳號。
- 本輪未變更客戶資料、未發送 LINE 訊息、未送出實際出價、未變更資料庫規則。
- 最新前端尚未部署；Android 安裝版、LINE App 與預設瀏覽器實際切換仍需部署後真機驗收。
