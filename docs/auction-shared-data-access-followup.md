# 競標共用個體資料權限後續計畫

## 已確認事實

2026-10-20 查核正式資料庫：`public.animals` 未啟用 RLS，且 `anon` 有 INSERT、UPDATE、DELETE。競標場次與出價表已關閉這些直接改寫權限。

唯讀檢視另一個 `gencko-admin` 原始碼，確認個體維護直接使用公開客戶端，沒有登入流程。直接撤銷個體表訪客權限會破壞目前維護流程，因此這必須是跨兩個專案協調的修正，不應當作單一 SQL 開關。

## 建議實作順序

1. 在另一後台加入真正的 Supabase Google 管理員登入，使用伺服器保存的管理員設定，禁止信任前端旗標或 user_metadata。
2. 盤點該後台所有個體新增、修改、刪除、繁殖、健康與照片操作；為目前依賴訪客的寫入建立受保護介面或管理員 RLS。
3. 保留官網真正需要的公開欄位讀取；成本、買家、聯絡方式等欄位另查核公開範圍，避免以「全表可讀」代替公開展示契約。
4. 以可回滾測試驗證訪客與一般會員不能新增／改寫／刪除；指定管理員可完成既有工作，且競標上架、結算與核帳不受影響。
5. 協調部署後台登入與權限變更，再關閉訪客直接改寫；避免先關閉造成操作中斷，或只部署 UI 仍保留資料庫漏洞。
6. 舊後台若仍有直接操作競標表的入口，應遷移至現行受保護競標 RPC，或清楚引導至官網競標管理，不恢復公開寫入權限。
7. 重新執行兩個專案的管理回歸與正式站唯讀驗證，再確認可用於正式販售。

本文件是可實作的後續計畫，不代表風險已解除；本輪未更動另一後台。

參考：[Supabase RLS 關閉檢查](https://supabase.com/docs/guides/database/database-linter?lint=0013_rls_disabled_in_public)。
