# LINE 登入接續與首頁入口複驗

本輪接續 Android PWA 登入、官方 LINE 驗證及首頁四個入口的調整。修改保留在本機，未提交或部署。

## 已重現及修正

1. 多個分頁同時發起不同登入會交錯呼叫 SDK、覆寫共用 PKCE 狀態。現在發起 LINE／Google、登入交換與登出使用相同 Web Lock；同分頁仍有忙碌防重入。較舊且沒有 Web Locks 的瀏覽器保留原有降級行為。
2. 登入交換成功後仍等候清理請求，斷線時延遲完成。清理改為背景執行；失敗由既有到期排程清除，不阻擋已建立的 session。
3. 接續碼尾端附加多餘段落仍被接受。現在要求完整的兩段格式，且必須對應原 App 的待完成流程。
4. 輸入區關閉再出現時殘留上一輪接續碼及錯誤。現在依流程與顯示狀態清空。
5. 剪貼簿權限視窗延遲返回時，即使已取消／離開，仍可能啟動登入。現在檢查元件生命週期與請求代次；舊結果不再生效，也不覆蓋新的手動輸入。
6. 待接續輸入區沒有取消入口。已補上取消本次登入；清除本機待接續紀錄，不變動永久出價驗證。
7. 回程頁讀取接續碼遇到暫時錯誤，只能重走授權。已補原頁重試，保留本次有效流程。
8. 回程頁放置超過有效期，仍顯示可複製的舊碼。伺服器 Cookie 與 API 現在附期限；逾時清除顯示，複製動作執行前也再次檢查。
9. 手機休眠、裝置時間偏差可能影響前端期限顯示。剩餘期限以伺服器時間校準，同時檢查單調時間及經過的裝置時間；實際交換仍由後端決定是否有效。
10. 等待貼碼時停止輪詢，無法及時得知後端流程失效。改為前景每約 15 秒補查，背景與離線不輪詢，正常待回程仍每 3 秒補查。
11. 首頁入口在 320、390、1280、1440 寬度、兩倍字體時裁切標題。改為空間不足時換行，保留照片左下方位置、原欄數與手機兩欄。

## 驗證證據

- 31 項單元測試通過：接續儲存、一次性交換、取消、清理斷線、嚴格格式、伺服器期限、休眠／時鐘變動、AES-GCM、會員身分及登出。
- 35 項瀏覽器流程通過：共用／隔離瀏覽器的實際 SDK PKCE challenge 與 verifier 核對、重載登入、跨分頁互斥、接續碼重試與過期、剪貼簿競態、取消、LINE 官方驗證、出價資格、領標、付款回報、管理員解除限制及結標列表。
- 另 3 項本機實際 API 測試通過：期限與 no-store、過期／不符流程／缺少證明拒絕、跨站拒絕。使用隔離測試 Cookie，不呼叫正式授權交換。
- 首頁 320、390、768、960、1024、1280、1440、1920 共 8 種寬度：無水平溢出、入口至少 44px、連結正確；桌機位置及底部對齊、手機兩欄與鍵盤 Enter 導向通過。
- 首頁 320、390、1024、1280、1440 共 5 種寬度的兩倍字體：四個標題均未裁切，頁面未水平溢出。
- 本輪 Supabase 唯讀檢查：接續表 RLS 啟用、匿名不可讀、會員不可直接寫、最近到期清理成功。

- 隔離正式建置成功（程序結束碼 0）；6 項競標 SSR 檢查通過：最高價、無出價、資料故障不捏造價格、結標禁止索引、詳情及列表資料不可注入腳本。
- `git diff --check` 通過，沒有差異格式錯誤。

## 實機限制

沒有代替使用者在實體 Android 手機上重新操作原生 LINE → 系統瀏覽器 → 已安裝 App。隔離瀏覽器模擬通過，不代表所有手機都會由系統自動切回 App；不同儲存區仍需複製接續碼回原 App 完成登入。

登入接續碼只用於本次登入；傳送給官方 LINE 的出價驗證碼是另一個流程。原本一次驗證、永久保存在 Supabase 的出價資格未重置，本輪未變更客戶、出價、付款或棄標資料。
