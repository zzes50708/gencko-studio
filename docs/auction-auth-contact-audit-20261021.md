# 客人登入與官方 LINE 驗證排查（2026-10-21）

## 本輪修正

1. 官方 LINE 狀態尚未回應時直接顯示建立綁定，造成登入失敗的誤解：改顯示確認狀態。
2. 狀態查詢失敗仍顯示建立綁定：改提供重新確認，不憑錯誤推定客人尚未驗證。
3. 未確認狀態仍可發起建立綁定：動作檢查 required、ready 與 restricted。
4. 已過期的綁定碼仍提供傳送入口：拒絕過期回應，讓客人重新建立。
5. 一般登出預設撤銷其他裝置工作階段：改為 scope local。
6. 登出 API 回傳錯誤卻清除畫面會員：改保留狀態並提示重試。
7. 舊 LIFF 登出發生例外會中斷網站清理：網站成功登出後，LIFF 與舊快取清理各自容錯。

## 已核對的流程界線

- LINE 登入建立網站會員工作階段，不代表已加入官方帳號，也不代表已傳送官方聯絡驗證。
- manual_claim 模式的 required=false：不用在出價前額外綁定；查核成功後開放出價。
- 查核失敗不能當成 required=false；限制出價仍優先阻擋。
- Google 保留管理及原帳號歷史紀錄，新出價使用 LINE。
- 綁定碼與各場得標領標碼分開管理；一般聯絡不會撤銷其他場次領標碼。
- Webhook 檢查原始內容簽章，僅接受一對一 LINE 使用者事件；暱稱查詢失敗不丟棄領標事件。
- Android 安裝模式、一般瀏覽器、返回前景與重讀工作階段有隔離瀏覽器測試；無法據此宣稱真實 Android／LINE App 回程已驗收。
