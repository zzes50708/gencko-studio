# 競標完整流程補查：會員歷史紀錄（2026-10-21）

這輪沿登入→出價→價格更新→會員紀錄→領標→核帳與限制檢查，發現「我的專區」歷史紀錄未沿用前幾輪的完整資料及狀態處理，補查後集中修正。測試通過不代表已部署或所有實機問題已排除。

## 發現與修正

1. get_my_auction_bids 只呼叫一次，受 API 上限截斷。實際以 1,201 筆重現只顯示 1,000 次、最高價 1,199，完整資料應為 1,201 次、最高價 1,400。改每頁 500 筆、固定排序、跨頁去重，讀完再顯示。
2. RPC 為 null 卻被當成無出價。改區分合法空陣列與異常回應，逐筆核對場次、金額及時間；失敗提示重試。
3. 場次 metadata 一次塞所有 ID，網址可能過長且受上限截斷。改每批最多 100 個 ID；末批失敗不回傳半份可信結果。
4. 狀態只看結標時間，暫停與預約皆可能誤報競標中。補讀 status／start_time，沿用公開頁 auctionState。
5. 狀態使用裝置 Date.now，快兩天可能把仍開放的場次誤報結標。改用已校準的 auctionNow。
6. 開標與結標邊界不會自己變動。可見頁面每秒更新狀態；實際用時鐘快轉確認尚未開標→競標中→已結標。
7. 本人金額標成「最高出價」，容易被看成全場最高。明確改為「我的最高出價」。
8. 沒有照片時仍請求不存在的外部 placeholder.jpg。改用既有 ArticleImage 的空圖狀態，不發失效圖片請求；截圖複驗再補上可指定的 emptyText，本區顯示「尚無個體照片」，其他文章保留原文案。
9. 同帳號重新讀取 session 會產生新物件，原 watch 會清空整份紀錄並重抓。改監聽穩定的會員識別與可讀身分。
10. 返回可見分頁、重新連線與進入競標分頁時原先不保證補查。加入背景更新與可見時 15 秒補查，等待期間保留卡片；只在競標分頁發起背景查詢。
11. 換帳號或離頁僅丟棄結果，舊查詢仍消耗網路。以 AbortController 取消，並保留 revision 避免舊結果回寫。
12. FAQ 仍稱 Google 可新出價、只能 Google 查看紀錄。改為新出價限 LINE、歷史資料用原帳號查看且不自動合併；詢問直購不代表保留或成交。

前三個瀏覽器案例先重現失敗，再修正通過；另驗證狀態邊界、同帳號更新不清空、背景等待保留及登出清除。會員資料只由自己的授權 RPC 取得，不傳前端會員 ID。
