# LINE 競標與出價者聯絡驗證

> 本文件保留各階段調查紀錄；目前採用的自行領標、結標起算期限及人工核帳規則，以 [最終流程](auction-manual-claim-workflow.md) 為準。

## 已確認根因

- LINE 網頁登入回傳 HS256 ID token；目前 Supabase 自訂 OIDC 流程依公開 JWKS 期待 ES256，實際登入被拒絕。
- 已新增 `custom:line-oauth` OAuth2 供應商，透過 LINE userinfo 驗證會員；保留 PKCE，允許沒有 email 的 LINE 會員。
- 原先開發模式將 JS 授權工具以原生模組載入，編輯後仍使用快取。授權工具改為 TypeScript，已確認 Nitro bundle 包含新的供應商判斷。
- LINE 登入不等於已與官方帳號建立聊天；尚未建立聊天時，不承諾可以直接開啟對話或收到通知。

## 已完成

- Google 與 LINE 擇一出價；只信任伺服器驗證的會員及 app_metadata。
- 實際 LINE OAuth 登入成功，建立具穩定 LINE subject 的會員。
- 加入競標頁「建立 LINE 聯絡」，預填場次與會員編號；由會員自行確認傳送，不自動發訊息。
- 新增 `/auction-management` 管理入口，Google 登入後依場次查詢出價者。
- 新增管理員專用 RPC，從 auth.users 實際權限設定查核，不信任使用者可修改的個人資料。
- 查詢包含出價暱稱、會員編號、驗證過的 LINE 身分與對話入口；訪客不得執行，一般會員被拒絕。
- 使用者指定的 Google 管理帳號已透過資料庫授權；未把 email 放入原始碼。

## 驗證證據

- 單元及 API 回歸：37 個檔案、215 項通過。
- 管理頁 E2E：登入提示、權限拒絕不殘留私人資料、320/390/1440 寬度通過。
- 資料庫回滾測試：無 email LINE 會員能成立出價、穩定擁有者與 LINE 身分一致；一般會員及偽造 user_metadata 管理員被拒絕，真正管理員能查核身分。
- SQL 測試完整回滾，並未新增永久測試出價。

## 仍待實測與發布

- 使用者已手動完成 500 元 LINE 出價；資料庫核對為正確 LINE 會員，場次共 4 筆、最高 500 元。
- 已實際以指定 Google 管理員登入管理頁，成功查出 4 筆測試場次紀錄及最高 500 元 LINE 出價的聊天入口。

## 2026-10-16 聊天入口及管理列表修正

- 已移除以 LINE Login 使用者 ID 拼接後台聊天網址的做法；該路徑實測導向 404，不可宣稱能開啟對話。
- 改為官方收件匣入口及複製 LINE 名稱；需於收件匣核對會員傳來的場次及會員編號，尚不提供自動選取正確對話。
- 管理頁改為場次列表，點選顯示場次資訊及出價者，可返回列表，不須輸入場次編號。
- 一般 Google／LINE 會員不顯示管理列表及查詢操作；資料庫仍再次驗證管理員權限。
- 當次查核僅一位授權管理員，為使用者指定帳號。
- 215 項單元／API 測試與 3 項管理頁 E2E 通過。以實際管理員瀏覽器驗證兩個場次、點入測試場次看到四筆出價及新收件匣入口。
