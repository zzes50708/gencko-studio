# 競標自行領標與人工核帳

## 最終規則

- Google 或 LINE 擇一登入出價，不要求兩者同時登入。
- 得標者在競標詳情或會員得標紀錄產生並複製確認訊息，自行貼到官方 LINE 領標。
- 訊息的場次與金額來自伺服器結算結果；驗證碼只能由該場得標者產生，15 分鐘有效，各場獨立。
- LINE Webhook 驗證原始訊息簽章後，核對驗證碼及登入身分，記錄領標時間與聯絡身分。不以暱稱判斷所有權。
- 新流程不自動推送得標通知。付款期限從最終結標時間起算 24 小時，包含競標延長。
- 收款由管理員主動核帳，客人不能自行回報付款來停止逾期處理。管理員可填寫原因延後期限。
- 到期未核帳即限制網站出價，不封鎖 LINE；即使排程稍晚，出價時仍檢查到期紀錄。
- 有正當理由可由管理員解除限制；逾期補款可核帳，但只解除已核帳這一場造成的限制。
- 手動解封亦僅解除所選棄標場次；其他場次未解決時仍禁止出價，已付款等狀態不能執行解封。
- 結標場次公開保留 48 小時，之後從列表隱藏，資料與管理紀錄不刪除。
- 舊場次不批次套用新流程；啟用後只自動納入新建場次。

## 管理方式

管理員登入後至 `/auction-management`，從列表選擇場次。填寫操作原因後，可確認收款完成核帳、延後付款期限、標記棄標或解除出價限制。資料庫再次檢查實際管理員設定，不信任使用者可修改的資料。

## 驗證證據

- 實際 LINE 出價與 Google 出價均已成立並核對身分。
- 兩個本人登入身分並行送出相同 700 元：只成立一筆，另一筆拒絕；截止時間延長 3 分鐘。
- 官方 LINE 連線測試已由本人確認收到；新版複製領標訊息亦由本人實際傳送，資料庫記錄領標成功。
- 實際管理介面已測試延期、解除限制及核帳；非販售測試場次最後為已核帳，沒有出價限制。
- 單元及 API：38 檔案、223 項通過。
- 介面：領標／付款／解除限制／結標入口／48 小時列表等 5 項，以及原管理頁權限等 3 項通過。
- 出價故障瀏覽器回歸通過，涵蓋斷線保留同一請求、重複點擊、登入恢復、截止後重試與手機表單。
- 原流程資料庫回滾測試 20 項、新領標與核帳回滾測試 13 項通過。測試完整回滾，不留下臨時場次或出價。
- 上線後複驗新增 5 項跨場次解封檢查，新流程合計 18 項通過；測試內暫停自動納入，完整回滾後恢復正式設定。任一檢查失敗會直接回傳測試錯誤。
- 再新增本場已解封、會員仍有其他限制的管理查詢檢查，新流程合計 19 項；管理頁分開顯示本場限制及整體出價狀態，避免重複解封。
- 核帳請求成功但狀態重讀失敗時，明確提示操作已送出，只提供重新讀取；重試成功清除舊錯誤。會員端採相同處理，讀取回應以請求序號避免較舊資料覆蓋新資料。
- 即時事件瀏覽器測試重現讀取途中第二筆出價遺漏；改為合併待更新事件並在讀取後立即補讀。模擬 WebSocket 的出價、密集出價、延長及結標事件均能更新原頁面，未發生重新導航。正式資料庫的 auctions、auction_bids 已確認加入即時發布；模擬測試不等同兩位真實客人的網路延遲保證。
- 列表亦訂閱出價與場次事件，讀取中合併更新；列表與詳情訂閱成功／重新連線即補查，列表恢復上網亦補查。共用場次讀取回傳同一工作 Promise，避免列表在初始化未完成時查空摘要；事件只觸發查詢，不直接覆蓋新資料，並納入場次刪除事件。
- 模擬列表密集更新、過期事件、摘要讀取被拒、online 恢復與實際 WebSocket 關閉後自動重連均通過；錯誤時不顯示舊摘要為最新價格。跨頁插入造成的同筆出價以 ID 去重，新增回歸檢查。
- 重現裝置時鐘不準導致列表提前隱藏結標場次及倒數錯誤：共用場次讀取先校時，48 小時資料庫篩選、公開列表分類與倒數改用伺服器取樣加單調時鐘；離線沿用上次樣本，不退回裝置時鐘。快／慢兩天及使用中改日期的隔離瀏覽器測試通過。
- 重現起標價 100、增額 100 卻要求第一筆 200 的落差：第一筆最低價改為正起標價，已有出價才加增額；零元起標第一筆仍為正增額。前端預填與資料庫一致，第一筆接受 100、後續拒絕 150 的回滾測試通過，核心資料庫檢查增加為 22 項。
- 暫停／未開放場次即使已超過時間，仍顯示暫停而非已結標，避免誤導為正常結算結果；實際出價與結標均仍由資料庫判斷。
- 額外用兩個資料庫交易並行驗證重新複製領標與 LINE 回傳：修正前重現死結，修正後兩個交易均完成並回滾；伺服器統一先鎖結算紀錄再鎖驗證碼。
- 非販售測試會明確提示不要付款，未操作其他既有個體或客人。

## 上線與運作

網站由 Git 主分支部署；Supabase 遷移及 `auction-workflow` Edge Function 另行部署。LINE secret 僅存 Supabase Edge Secrets，排程專用密鑰存 Vault，不寫入前端或 Git。

每分鐘排程負責結標及建立逾期限制紀錄。新流程維持 `fulfillment_mode=manual_claim`、`notifications_enabled=false`；網站部署完成後，才啟用結算排程及新場次自動納入。

## 已知邊界

- LINE 官方 URL scheme 不支援桌面版 LINE，因此提供完整文字複製；手機可使用預填訊息連結。
- 已證明簽章、身分與實際領標訊息連動；不宣稱可以阻止同一人另外建立完全不同的 Google／LINE 帳號。
- 銀行收款仍由工作室人工查核，系統不會自行宣稱收到款項。
- 全站另有既有、非競標資料表的 RLS／檢視權限提示，未在本次修改，避免影響既有後台。競標私人資料表不提供直接讀寫權限，透過受保護 RPC 存取。參考：[Supabase 資料庫權限檢查](https://supabase.com/docs/guides/database/database-linter)。
